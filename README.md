## 💡 한눈에

| 문제 | 우리 방법 |
|---|---|
| 다회용기는 늘지만, 회수 뒤 잔반 제거 · 애벌세척 · 랙 적재는 아직 사람 손이다 | 협동로봇 1대가 집기 → 잔반 → 닦기 → 헹굼 → 팔레트 적재를 시작 버튼 한 번으로 이어서 합니다 |
| 매장 · 게이트 단위 소형 셀에는 카메라 · 전용 설비를 두기 어렵다 | 카메라 없이 그리퍼 **파지 폭**, 관절 토크로 추정한 **무게 · 힘**, 세 신호로 판단합니다 |
| 위생 지침은 반납 수량 · 처리 기록을 요구한다 | 용기마다 무게 · 시간 · 결과를 SQLite에 남기고 운영 화면에 누적 KPI로 보여 줍니다 |
| 오류가 나면 셀이 서 버린다 | 예외 8종마다 재시도 · 격리 · 정지 · 재개를 정해, 사람이 필요한 때만 부릅니다 |

로봇과 그리퍼가 원래 가진 신호만으로 판단하고, **혼자 해결할 수 있는 실패는 격리하고 다음 용기로, 사람이 필요한 실패는 그 자리에 멈춰 안내**합니다.

```text
[시작] → ① 집기 → ② 무게(잔반 50 g 넘으면 털고 다시) → ③ 스펀지 홈 안착 → ④ 툴 집기 · 세제 · 닦기 · 툴 반납 → ⑤ 헹굼 · 물 털기 → ⑥ 팔레트 적재 → 다음 용기
예외: 빈 구역 건너뛰기 · 잔반 남음 → 격리 · 툴 놓침 / 툴 집기 실패 / 케이블 이상 → 멈춤 → 사람이 고치고 팔을 밀거나 화면에서 재개
```

<details>
<summary>배경 — 왜 다회용기 예비세척인가</summary>

경기장 일회용품 규제와 지자체 사업으로 다회용기 전환이 늘고 있지만, 병목은 **회수 뒤 세척**입니다. 세척센터에서도 본세척은 자동화됐지만 분류 · 애벌세척 · 랙 적재는 아직 사람 손이고, 경기 직후 수천 개가 몰리는 젖은 반복 노동이라 사람을 구하기 어렵습니다.

그래서 **두산 M0609 1대 + RG2로 예비세척 전처리(잔반 제거 → 닦기 → 헹굼 → 팔레트 적재)를 자동화하는 소형 셀**을 목표로 했습니다. 카메라 · 전용 설비 없이 매장 단위로 놓을 수 있게 하고, 시작 버튼 1회로 연속 처리하며, 오류가 나도 격리 · 재개로 운영을 이어 가고, 처리 기록을 남겨 위생 가이드라인의 기록 요구를 맞춥니다. 근거와 전체 요구사항은 [요구사항 문서](docs/01_요구사항_BR-SR.md)에 있습니다.

</details>

## ✨ 핵심 기능

### 🧽 그릇 · 컵에 맞춘 닦기
둘 다 접촉 하강으로 바닥을 찾은 뒤, 그릇은 바닥 나선 → **1.5 N 힘 제어로 벽면**을 돌고, 컵은 솔을 **위아래 ±15 mm · 손목 ±90°** 주기 운동으로 닦습니다.

<p align="center">
  <img src="docs/images/demo/demo_cup_wipe.gif" width="270" alt="컵 안쪽을 솔로 위아래 · 손목 회전하며 닦기"><br>
  <sub>컵 — 솔을 위아래로 움직이며 손목을 돌려 닦기(2배속)</sub>
</p>

<details>
<summary>자세히</summary>

- **툴:** 그릇은 수세미 툴(지름 90 mm), 컵은 수세미 솔(길이 95 mm)을 씁니다. 툴 홀더 2개의 비눗물에 담가 세제를 묻힙니다.
- **힘:** 그릇은 힘 제어로 벽면을 돌고(닦기 힘 평균 그릇 1 2.64 N · 그릇 2 2.06 N, 최대 6.91 N · 6.34 N), 컵은 힘 제어 없이 상한 10 N만 감시합니다. 상한 초과는 0번이었습니다.
- **상한을 넘으면:** 닦기를 즉시 멈추고 위로 빠진 뒤, 툴을 쥐고 있으면 한 번 더 닦습니다. 그래도 실패하면 사람 없이 격리 구역으로 보냅니다.

</details>

### ⚖️ 잔반 판정과 자동 털기
무게를 30번(0.5 s 간격) 읽은 중앙값에서 빈 용기 기준값을 빼고, **50 g을 넘으면 잔반통 위에서 털고 다시 잽니다.** 그래도 남으면 사람 없이 격리 구역으로 보냅니다.

<details>
<summary>자세히</summary>

- **저울 없이:** 전용 저울 없이 로봇팔 관절 토크로 추정한 툴 힘으로 잽니다. 그래서 측정 조건이 중요합니다 — 항상 HOME을 거쳐 같은 자세에서 재고, 빈 용기 기준값은 실행 직전에 다시 잽니다([트러블슈팅 2](#-트러블슈팅)).
- **결과:** 98 g 대용품 4번 중 4번 감지 · 빈 용기 8번 중 오판 0번(임계 50 g).
- **실시간 표시:** 재는 동안의 무게 표본을 운영 화면에 그대로 보여 줍니다(`/flow/weigh`).

</details>

### ⏸️ 바로 멈추고, 팔을 밀어 이어 가기
이동 명령을 비동기로 보내고 0.05 s마다 완료 · 정지 신호를 확인해 **이동 도중에도 그 자리에서 섭니다**. 툴 놓침 · 툴 집기 실패 · 케이블 이상으로 멈췄을 때는 원인을 치운 뒤 **팔을 한 번 가볍게(15 N) 밀고 손을 떼면** 1.5 s 뒤 이어 갑니다. 이런 멈춤은 화면의 [재개]로도 이어 갈 수 있고, 일시 정지는 [재개]로만 풀립니다.

<p align="center">
  <img src="docs/images/demo/demo_nudge_resume.gif" width="400" alt="멈춘 로봇팔을 손으로 가볍게 밀어 재개"><br>
  <sub>멈춘 팔을 가볍게 밀고 손을 떼면 다시 움직임</sub>
</p>

<details>
<summary>자세히</summary>

- **일시 정지:** 이동 도중에도 그 자리에서 멈추고, 재개하면 하던 동작부터 이어 갑니다. 닦기 동작 중이면 그 동작이 끝난 뒤 멈춥니다.
- **중단:** 멈춘 상태에서 중단하면 툴을 반납하고 용기를 격리한 뒤 다음 용기로 갑니다. 이력에는 "관리자 격리"로 남습니다.
- **안전:** 로봇 위치를 모르면 스스로 움직이지 않고, 비상 정지는 E-Stop입니다.

</details>

### 🛟 예외 처리 — 혼자 해결할 건 격리, 사람이 필요하면 그 자리에 멈춤
툴 놓침 · 툴 집기 실패 · 케이블 이상처럼 사람이 필요한 실패에서는 **쥔 것을 그대로 두고 그 자리에 서서** 원인을 화면에 알립니다. 사람이 고치면 툴 집기 · 무게 단계부터 다시 합니다.

<details>
<summary>상황별 처리 표</summary>

사람을 부르는 멈춤에서는 쥔 것을 그대로 두고 그 자리에 섭니다. 격리할 때는 곧게 위로 빠져 툴을 홀더에 반납한 뒤 옮깁니다. 로봇 위치를 모르면 스스로 움직이지 않습니다.

| 상황 | 로봇 | 사람 |
|---|---|---|
| 반납 구역이 비어 있다 | 그 구역을 건너뜁니다 | — |
| 털어도 잔반이 남는다 · 닦기 힘/시간 상한을 넘었다 | 닦기는 즉시 멈추고 위로 빠진 뒤, 툴을 쥐고 있으면 한 번 더 닦습니다(툴이 없으면 툴 놓침 멈춤). 그래도 실패하거나 잔반이 남으면 사람 없이 격리 구역으로 보내고 다음 용기로 갑니다 | — |
| 케이블 이상 · 툴 놓침 · 툴 집기 실패 | 그 자리에서 멈춥니다 | 케이블을 풀거나 툴을 홀더에 꽂고, 팔을 가볍게 한 번 밀고 손을 떼거나(1.5 s 뒤 움직임) 화면에서 재개 → 케이블은 무게 단계부터, 툴은 툴 집기부터 다시 합니다 |
| 운영자 일시 정지 · 중단 | 이동 도중에도 그 자리에서 멈춥니다(닦기 동작 중이면 그 동작이 끝난 뒤). 멈춘 상태에서 중단하면 툴을 반납하고 용기를 격리한 뒤 다음 용기로 갑니다(로봇 오류 · 케이블 이상 멈춤에서는 중단을 받지 않습니다) | 재개하면 하던 동작부터 이어 갑니다. 중단한 용기는 이력에 "관리자 격리"로 남습니다 |
| 로봇 오류(보호 정지 등) | 그 자리에서 멈춥니다(예외였으면 곧게 위로 한 번만 시도). 사람 신호 전까지 움직이지 않습니다 | 밀기 · 재개 → 그리퍼만 열리면 쥐고 있던 물건을 받습니다 → 화면 재개 → 곧게 위로 → HOME → 다음 용기 |

실패 코드별 전체 목록(닦기 힘 · 시간 상한, 집기 실패, 팔레트 가득 등 포함)은 [설계 문서 §7](docs/03_설계_SDD.md)에 있습니다.

</details>

## 🌱 배운 점 · 한계

**배운 점**

- 인터페이스를 먼저 고정하니, 로봇 1대를 나눠 쓰는 4명이 로봇 없이도 병렬로 개발할 수 있었습니다.
- 로봇팔의 힘 센서로 잰 무게는 케이블 같은 하드웨어 요인에 크게 흔들렸습니다. 값이 이상하면 코드보다 측정 조건부터 확인해야 합니다.
- 바뀐 것마다 검증 수준(자동 시험 · 가상 · 실기)을 기록하게 하니, 실기 확인 전인 변경이 확인된 것처럼 병합되는 일을 막을 수 있었습니다.

**한계와 다음 과제**

- 용기당 사이클 타임이 153 ~ 219 s(배속 1.0 · 9/29)로 목표(90 s)에 못 미쳤습니다. 단계별 시간은 0.5 배속(9/23)에서만 기록했는데, 재파지 · 헹굼(56 ~ 84.5 s)과 적재 + HOME(41.5 ~ 60 s)이 가장 길었고, 무게 단계(HOME 경유 + 안정 대기 8 s)도 35 ~ 38.5 s(잔반 털기 때 118.5 s)를 차지했습니다.
- 닦기 동작 중에 일시 정지를 누르면 그 동작이 끝난 뒤 멈춥니다(컵 주기 운동 약 13 s). 즉시 멈추고 재개 때 닦기를 처음부터 하도록 바꾸는 것이 다음 과제입니다.
- 헹굼은 과정 안전 규정에 따라 물 없이 모션만 했고, 잔반은 대용품으로 시험했습니다.
- 격리 구역이 그릇 · 컵 공용 한 곳이라 다음 격리 전에 사람이 치워야 합니다.
- `cell.yaml` 좌표는 우리 워크셀 기준이라 다른 셀에서는 다시 티칭해야 합니다.

## 🙋 내 역할 — 박진용

**F3 접촉 닦기 · 공용 힘 함수 · 안전 담당** — 세제 담금 · 그릇/컵 닦기(F3), 팀 공용 힘 · 접촉 함수(`force.py`), 안전 파라미터를 맡았고, 스펀지 고정틀도 직접 만들었습니다.

### 1. 어떻게 설계했나
- 카메라 없이 닦아야 해서 위치만으로는 용기 높이 편차를 못 맞춤 → "바닥은 힘으로, 벽은 치수로"
  - 바닥은 접촉 하강(`contact_down`)으로 찾음
  - 벽 반지름은 고정 치수로 계산 — (그릇 안지름 110 − 수세미 90) / 2 + 4 = 14 mm
- 나선은 순응만, 벽면은 순응 + 힘 제어 — 힘 방향 = 이동 방향이면 힘 제어가 이동을 막기 때문
- F3는 노드가 아닌 함수 모음, 실패는 예외가 아니라 결과 코드로(OK · TOOL_LOST · FORCE_LIMIT · TIMEOUT · ROBOT_ERROR)
- 두산 API를 몰라도 쓰게 팀 공용 힘 함수를 제안(이슈 #7) → 분담 합의 후 `force.py` 구현

### 2. 어떻게 구현했나
- `force.py`(#20): 순응 · 힘 제어 on/off, 접촉 하강, 외력 읽기, 안전 후퇴, 나선 · 원호 · 주기 이동, 넛지 감지
- `soap()`: 손목 ±20° 비틀기 + Z ±5 mm 왕복, 보내기 전 회전 속도 사전 계산(126°/s, 한계 225°/s)
- `wipe_bowl()`: 빠른 하강 → 바닥 찾기 → 바닥 나선 → 1.5 N 힘 제어로 벽면 원호 3바퀴 + 좌우 비틀기
- `wipe_cup()`: 힘으로만 바닥 찾기 → 위아래 15 mm + 손목 ±90° 동시 왕복, 1 · 4번 관절 1.0° 넘으면 즉시 정지
- 툴 놓침(TOOL_LOST) 감시: 그립 폭 기준값 대비 그릇 1.0 · 컵 1.5 mm 넘으면 정지, 빈손으로 후퇴하지 않음 → 넛지 재개(#99)
- 안전: 로봇 위치를 모르면 자동으로 움직이지 않음(9/21 케이블 꼬임 사고 반영, #46), 안전 파라미터 표(SAFE-01)

### 3. 트러블슈팅
| 문제 | 원인 | 해결 |
|---|---|---|
| 0.1 mm 내려가자마자 "바닥"으로 오판 | 툴 무게가 미등록이라 공중에서도 Fz 약 2 N | 절대값 → 하강 전 대비 변화량으로 판정 |
| 나선 명령에 드라이버 전체가 멈춤 | Move Spiral은 시간 지정 전용인데 속도를 넣음 | vel · acc는 0, 시간만 넘기게 고정 |
| 같은 회전 명령이 실기에선 다른 관절을 돌림 | TCP 설정에 따라 TOOL 회전 채널 대응이 다름(Virtual은 반대) | TOOL rz만 사용 + 1 · 4번 관절 감시 |
| 6번 관절이 정격의 145 %(326.5°/s)로 돌았는데 알람 없음 | 회전 + 옆 이동 조합을 제어기도 못 거름 | 그 실험은 폐기, 회전 속도 사전 검사 추가 |
| 놓침 감지 뒤에도 빈손으로 한 번 더 움직임 | 실패 시 후퇴 로직을 그대로 탐 | TOOL_LOST면 그 자리에서 멈춤 → 넛지 재개 기능으로 발전 |

### 결과
| 항목 | 결과 |
|---|---|
| 그릇 세척 시간(속도 튜닝) | 38.2초 → 17.7초 |
| 닦기 힘 | 평균 그릇1 2.64 N · 그릇2 2.06 N · 상한(10 N) 초과 0 |
| 툴 놓침 판별 | 놓치면 폭 2 ~ 3 mm 변화 vs 정상 흔들림 0.1 ~ 0.2 mm → 확실히 구분 |
| 전체 흐름(팀) | 시작 1번으로 그릇 2 · 컵 2 무정지 완주 |

## 🚀 설치 · 실행

로봇 없이 Ubuntu 24.04 · ROS 2 Jazzy PC 한 대에서 흐름과 운영 화면을 돌려 볼 수 있습니다. ROS 2 설치부터 실제 로봇(PC 1대 · 2대)까지 전체 절차는 **[docs/setup.md](docs/setup.md)** 에 있습니다.

<details>
<summary>빠른 시작 — 받기 · 빌드 · 자동 시험 · 로봇 없이 실행</summary>

```bash
# 받기 · 빌드 · 자동 시험 (ROS 2 Jazzy · colcon · pytest 설치 뒤 — setup.md 1~2)
cd ~ && git clone https://github.com/rokey9-d2/rokey_9_pjt1_D2.git rokey_pjt01_ws
cd ~/rokey_pjt01_ws && source /opt/ros/jazzy/setup.bash
colcon build --symlink-install && source install/setup.bash
python3 -m pytest -q src

# 로봇 없이 실행 (운영 화면 부품 설치 뒤 — setup.md 3) → 브라우저 http://localhost:8000 에서 시작
export ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST
ros2 launch prewash_bringup prewash_mock.launch.py
```
