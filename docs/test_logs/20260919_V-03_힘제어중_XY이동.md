1. **힘제어를 켠 채 X·Y 로 움직일 수 있는가** (= 눌러 붙인 채 문지를 수 있는가)

## 1. 확정된 닦기 방식 (9/20 실기 확인)

```
HOME → 빠른 하강 135 mm(작업대 상판 1 cm 위)
  → 순응 ON 상태로 3 mm 씩 내려가며 바닥 찾기 (시작 힘 대비 2 N)
  → 찾은 자리 그대로 순응 ON 유지 (더 누르지도, 올리지도 않는다)
  → 바닥: **Move Spiral 한 번** (2.8바퀴 · 반지름 14 mm · 3 s · 좌우 비틀기 없음 · 힘제어 OFF)
  → 힘제어 ON (1.5 N, 공중 기준값 보정)
  → 벽면: 원호(Move C)를 이어 붙여 **반대 방향 3바퀴** + 손목 ±18° 좌우 비틀기
  → 힘제어 OFF → 순응 OFF → 그 높이에서 중심 복귀 → Z 만 올려 HOME
```
- 벽 반지름 = (그릇 안지름 − 툴 지름) / 2 + 벽 누름 = (110 − 90)/2 + 4 = **14 mm**.
  수세미가 물러서 벽에 눌려도 힘이 잘 잡히지 않는다 → 힘으로 찾지 않고 **크기로 계산**하고, 벽 쪽으로 4 mm 밀면서 돈다(9/20 결정).
- 8자(Move Periodic) 방식은 폐기(9/19). 힘으로 벽 찾기도 폐기(9/20).

## 3. 회차에서 나온 사실 (근거)

### A. 힘제어를 켠 채 X·Y 로 움직일 수 있다 ✅
4회차에서 접촉을 유지한 채 문질렀다. SDD §9.9 의 대안("순응 + 위치 2~3 mm 누르기")은 필요 없다.

### B. 공중에서도 Fz 가 2.0~2.3 N 잡힌다 (툴 무게·센서 치우침)
- 실행마다 1.92 · 2.00 · 2.34 N 로 다르다. 툴이 가벼워 무게 측정이 어려워 **툴 무게 등록으로는 해결할 수 없다.**
- 6회차에서 이 값 때문에 `contact_limit_n = 3` 을 절대값으로 보던 `contact_down` 이 **깊이 0.1 mm 에서 접촉**으로 판정했다.
- → `contact_down` 을 **시작 힘 대비 변화량**으로 고쳤다(PR #24). 목표 힘도 같은 이유로 덜 눌릴 수 있다(§5 남은 것).

### C. 벽은 **힘 크기로 구분할 수 없다**
- 중심에서 바깥으로 갈 때 솔은 거의 **반지름 방향으로 직진**한다 → 마찰이 **안쪽**으로 걸려 벽과 방향이 같다.
- 6회차 실측: 반지름 4.8 mm 에서 안쪽으로 **5.1 N**(마찰) / 5회차 진짜 벽 **5.7 N** — 크기도 겹친다.
- 문지르는 중 옆 힘은 마찰만으로 **5~14 N** 까지 튄다.
- → 벽 판정을 **명령한 반지름을 못 따라간 거리(gap)** 로 바꿨다. 순응(X·Y 3 N/mm)이라 벽에 막히면 실제 위치가 따라오지 못한다.
  막히지 않은 구간의 gap 은 실측 **1.5 mm 이하**(7회차 98 걸음, 평균 0.41 · 최대 1.46) → 기준 **2 mm**.

### D. 솔은 그릇 벽을 **타고 넘을 수 있다**
- 7회차에서 반지름 82 mm(그릇 밖)까지 나가는 동안 gap 은 1.5 mm 이하였다. Z 는 힘제어라 솔이 벽 경사를 타고 올라간다(올라간 높이 3.5 mm).
- → 올라간 높이가 `climb_max_mm`(8 mm)를 넘으면 벽으로 본다(안전 판정). 7회차는 접촉 오판으로 애초에 솔이 바닥에 없었던 것이 근본 원인.

### E. 부드러움 · 속도
- 걸음마다 목표에서 멈추면 뚝뚝 끊긴다 → 목표 앞에서 다음 걸음으로 **이어 붙인다**(blend).
- 이어 붙이기가 크면(4 mm) 손목 비틀기가 상쇄돼 사라진다(Virtual 실측 ±2°) → **손목은 두 걸음에 한 번만** 방향을 바꾸고 이어 붙이기를 키웠다.
- 손목 회전은 M0609 J6 최대(225°/s) 근처라 **회전 속도로는 더 빨라지지 않는다** → 한 걸음·나선 간격을 넓혀 시간을 줄였다.
- 그릇이 스펀지 구멍 안에서 흔들린다(구멍이 그릇보다 크다) → 벽을 세게 밀지 않도록 **벽을 2 mm 만 누른 채** 돈다.

### F. 두산 모션 API 에서 배운 것 (9/20)
- `move_spiral` 은 **속도(vel)로 부르면 드라이버(dsr_controller2)가 통째로 멈춘다** — 다른 서비스도 응답하지 않아 브링업을 다시 켜야 한다. 반드시 `vel=[0,0]·acc=[0,0]` + `time` 으로 부른다.
- 파이썬 API 는 vel 을 생략하면 거부한다(`Invalid value : vel, v` → `DR_Error` → `rclpy.shutdown()`, TS-05).
- **반경 대비 회전 수·시간이 과하면 반환은 0 인데 시작조차 하지 않는다.** 그래서 rig 는 도는 동안 실제 반지름을 보고, 목표의 절반도 못 가면 오류로 멈춘다.
- `Move B`(moveb) 는 이 드라이버에서 시작되지 않았다(반환 0, 움직임 없음) — 쓰지 않는다.
- 걸음마다 힘·위치를 읽으면 **로봇이 매 걸음 선다**(서비스 왕복 30~60 ms). 도는 중에는 위치를 읽지 않고 힘만 가끔 확인한다.

### G. 수세미(스펀지) 때문에 달라지는 것
- 힘이 **늦게** 올라온다 → 접촉 판정 2 N, 걸음 3 mm. 실측 접촉 깊이는 12~17 mm 로 실행마다 다르다.
- 벽에 눌려도 힘이 잘 안 잡힌다 → 벽 찾기를 힘으로 하지 않고 **크기로 계산**한다.
- 힘제어로 목표 힘을 주면 무른 수세미가 계속 파고들어 작업대를 친다 → 목표를 1.5 N 으로 낮추고, 높이는 명령하지 않는다.
