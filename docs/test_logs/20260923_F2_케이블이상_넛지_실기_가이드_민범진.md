# F2 로봇팔 케이블 이상 감지 및 넛지(Nudge) 실기 가이드

> **작성자**: F2 담당 민범진  
> **대상**: 팀원 전체 (로봇 조작자, F4 HMI 대시보드 담당, PM)  
> **적용 모듈**: `f2_sense_flow` (`sense.py`, `flow.py`, `flow_node.py`), `params.yaml`  

---

## 1. 기능 개요 및 동작 흐름

로봇이 용기 무게를 측정할 때 그리퍼 케이블이 팽팽하게 당겨지면 툴 힘센서에 지속적인 진동/떨림(Jitter)이 발생하여 부정확한 계측과 케이블 손상을 유발할 수 있습니다.  
이를 자동으로 감지하여 **후퇴 동작 없이 즉시 모션을 일시 정지(PAUSE)**하고, 사용자가 케이블을 정돈한 후 **로봇을 가볍게 톡톡 두드리면(Nudge)** 상태를 재확인하여 안전하게 작업을 재개합니다.

### 동작 시퀀스

```text
[무게 측정 단계 (weigh)]
        ↓
케이블 장력/떨림 이상 감지 (jitter_g > max_weigh_spread_g)
        ↓
🚨 후퇴 동작(safe_retreat) 없이 현재 모션 즉시 PAUSE
        ↓
대시보드 알림 및 사용자 안내 메시지 전송
"케이블 상태를 확인해주세요. 확인 후 로봇을 가볍게 톡톡 두드려 주세요."
        ↓
[PAUSED 유지 상태에서 사용자 톡톡(Nudge) 감시]
        ↓
사용자가 케이블 정돈 후 로봇을 "톡톡" 가볍게 두드림 (또는 HMI 재개 버튼)
        ↓
"재개 요청 감지 — 케이블 상태를 재확인하고 있습니다..."
        ↓
[정지 상태에서 케이블 장력 재검증 (recheck_cable)]
       ↙                                      ↘
[정상: jitter_g ≤ 상한]              [이상 지속: jitter_g > 상한]
       ↓                                      ↓
"케이블 정상 확인 — 작업 재개"       "케이블 이상 지속: 다시 톡톡 두드려 주세요"
       ↓                                      ↓
모션 resume & 중단 단계 재개(RETRY_STEP)      PAUSED 유지 (계속 톡톡 대기)
```

## 2. 실기 로봇 테스트 방법

### 2.1 테스트 전 사전 점검
1. **DDS 도메인 격리 확인**:
   ```bash
   rosinfo
   # ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST (solo) 상태인지 확인
   ```
2. **실기 브링업 실행**:
   ```bash
   sod && sodreal
   # 로봇 컨트롤러 IP 192.168.1.100 연결 및 티치펜던트 제어권 해제 확인
   ```
3. **빌드 및 환경 로드**:
   ```bash
   cbc
   ```

---

### 2.2 테스트 시나리오 및 실행 절차

#### 시나리오 A: 정상 동작 확인 (Baseline)
1. 케이블을 느슨하고 여유 있게 정돈합니다.
2. `flow_node` 또는 통합 런치를 실행합니다:
   ```bash
   ros2 launch prewash_bringup prewash.launch.py vel_scale:=0.3
   ```
3. HMI 시작(또는 서비스 호출) 후 용기를 집어 WEIGH 단계로 진입할 때:
   - 정상 무게 측정 후 멈춤 없이 다음 공정(SEAT/WIPE)으로 정상 진행되는지 확인합니다.

---

#### 시나리오 B: 케이블 이상 감지 및 모션 즉시 정지 확인
1. **이상 상황 모의**:
   - 실기 테스트 시 케이블을 손으로 가볍게 살짝 당겨 팽팽한 상태를 유지하거나,
   - 또는 테스트를 위해 임시로 `params.yaml`의 `max_weigh_spread_g`를 낮게(예: `10.0`) 설정합니다.
2. 로봇이 WEIGH 자세에서 무게 측정을 시작합니다.
3. **확인할 동작**:
   - ✅ 로봇이 위로 올라가는 후퇴 동작(`safe_retreat`)을 **절대 하지 않고**, 그 자세 그대로 **즉시 멈춤(PAUSE)**하는지 확인.
   - ✅ `/flow/state` 토픽의 `step`이 `'PAUSED'`로 바뀌는지 확인:
     ```bash
     ros2 topic echo /flow/state --field message
     # "케이블 상태를 확인해주세요. 확인 후 로봇을 가볍게 톡톡 두드려 주세요." 출력 확인
     ```

---

#### 시나리오 C: 톡톡(Nudge) 감지 및 정상 복구 재개 확인
1. 시나리오 B로 PAUSED 상태가 된 것을 확인합니다.
2. 당겨져 있던 그리퍼 케이블을 손으로 풀어서 여유 길이를 충분히 확보합니다.
3. 그리퍼 뭉치나 로봇 말단 부근을 손가락/손바닥으로 **"톡-톡"** 가볍게 2회 두드립니다.
4. **확인할 동작**:
   - ✅ 터미널/로그에 `👉 톡톡(넛지) 감지 — 외력 변화량 ... N >= 임계 ... N` 출력 확인.
   - ✅ 상태 메시지가 `"재개 요청 감지 — 케이블 상태를 재확인하고 있습니다..."`로 전환.
   - ✅ 약 5~7초간 정지 상태에서 장력 재측정 후 `"케이블 정상 확인 — 작업을 재개합니다"` 출력.
   - ✅ 로봇이 멈췄던 WEIGH 단계부터 이어서 정상적으로 공정을 재개하는지 확인.

---

#### 시나리오 D: 이상 지속 시 정지(PAUSED) 유지 확인
1. 시나리오 B로 PAUSED 상태가 된 상태에서, **케이블을 여전히 팽팽하게 당긴 채로** 둡니다.
2. 로봇을 "톡-톡" 두드립니다.
3. **확인할 동작**:
   - ✅ 톡톡은 감지되나, 재측정 결과 상한을 초과하여 작업을 재개하지 않음.
   - ✅ 로봇이 움직이지 않고 PAUSED 상태를 계속 유지함.
   - ✅ 메시지가 `"케이블 이상 지속(떨림 ... g > 상한 ... g): 케이블 확인 후 다시 톡톡 두드려 주세요"`로 갱신됨.

---

#### 시나리오 E: HMI 버튼과의 연동 확인
* **HMI Resume 버튼**: 톡톡 두드리는 대신 HMI 대시보드에서 `재개(/flow/resume)`를 눌러도 동일하게 상태 재검증을 거쳐 정상일 때만 재개됩니다.
* **HMI Abort 버튼**: 이상 상태에서 정지가 지속되어 해당 용기를 포기하고자 할 때 `중단(/flow/abort)`을 누르면, 모션 일시정지가 안전하게 풀리고 기존 격리 회수(`HOME → 격리함 → HOME`) 절차로 전환됩니다.

## 3. 파라미터 설정 및 수정법 (튜닝 가이드)

모든 임계값과 시간 설정은 **`src/cobot_common/config/params.yaml`**의 `f2` 절에 정의되어 있으며, 코드 수정 없이 YAML 값만 변경하면 즉시 반영됩니다.

```yaml
f2:
  limits:
    # 🔗 케이블 장력 이상 판단 기준 (jitter: 추세를 제거한 순수 떨림 10~90% 폭)
    max_weigh_spread_g: 50.0       # 기본값: 50 g (실측: 정리 후 25~35 g / 팽팽할 때 45~70 g)

  nudge:                           # 🆕 케이블 넛지(톡톡) 및 재검증 설정
    force_threshold_n: 5.0         # 톡톡 감지 외력 변화량 임계값 (기본값: 5.0 N)
    poll_gap_s: 0.05               # 외력 모니터링 폴링 간격 (기본값: 0.05 s = 20 Hz)
    recheck_samples: 10            # 톡톡 후 상태 재검증 표본 수 (10회 x 0.7s ≈ 7초 소요)
```

### 상황별 파라미터 조정 팁

| 현상 | 원인 | 권장 수정법 |
|---|---|---|
| 케이블이 정상인데도 자꾸 케이블 이상 경보가 뜸 | 주변 진동이나 로봇 상태에 비해 판정 기준이 너무 민감함 | `f2.limits.max_weigh_spread_g`를 `60.0` 또는 `65.0`으로 상향 |
| 케이블이 팽팽한데 이상 감지가 안 됨 | 기준 상한이 너무 높음 | `f2.limits.max_weigh_spread_g`를 `40.0` 또는 `45.0`으로 하향 |
| 로봇을 톡톡 두드려도 인식을 못 함 | 두드림 감지 임계값이 너무 높음 | `f2.nudge.force_threshold_n`을 `3.0` 또는 `4.0`으로 하향 |
| 로봇 근처를 지나가거나 가벼운 진동에도 톡톡으로 인식됨 | 두드림 감지가 너무 예민함 | `f2.nudge.force_threshold_n`을 `7.0` 또는 `8.0`으로 상향 |
| 톡톡 후 재검증 대기 시간이 너무 길어 답답함 | 재검증 샘플 수가 많음 | `f2.nudge.recheck_samples`를 `6` 또는 `7`로 축소 (약 4~5초) |

## 4. 대시보드(F4) 연동 가이드

대시보드 담당자(F4 황인재)는 `/flow/state` 토픽의 다음 필드를 읽어 화면에 표시하면 됩니다.

1. **상태 표시**:
   - `step == 'PAUSED'`이고 `message`에 `'케이블'` 문구가 포함되어 있으면, 화면에 **[케이블 점검 필요]** 경고 팝업 또는 뱃지 활성화.
2. **사용자 유도 문구 표시**:
   - `message` 문자열을 화면 상단 안내 배너에 그대로 표시:
     - 대기 중: `"케이블 상태를 확인해주세요. 확인 후 로봇을 가볍게 톡톡 두드려 주세요."`
     - 재확인 중: `"재개 요청 감지 — 케이블 상태를 재확인하고 있습니다..."`
     - 실패 시: `"케이블 이상 지속: 케이블 확인 후 다시 톡톡 두드려 주세요"`
3. **버튼 제어**:
   - 사용자가 로봇을 직접 두드려도 재개되지만, 화면의 `[재개]` 버튼을 눌러도 동일하게 안전 재검증 루틴이 동작하므로 기존 UI 버튼을 그대로 유지합니다.
4. **오디오 피드백 (웹 비프음)**:
   - HMI(`Monitor.jsx`) 및 로컬 시험 페이지(`test.html`)에 브라우저 내장 **Web Audio API 비프음(`playBeep`)**이 내장되어 있습니다.
   - 톡톡 감지 시 `message`가 `"재개 요청 감지..."`로 변경되는 순간, 브라우저 스피커를 통해 고주파 디지털 비프음("삑!", 1500 Hz 사각파, 0.16초, 볼륨 0.75)을 1회 자동 재생하여 현장 소음 속에서도 청각적으로 넛지 인식을 즉각 확인할 수 있습니다.
