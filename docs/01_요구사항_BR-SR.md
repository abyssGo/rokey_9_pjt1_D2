## 1. 비즈니스 요구 (BR)

### 1.1 배경과 문제
- 야구장·축구장은 일회용품 규제(자원재활용법, 2022~)와 지자체 사업(서울 잠실 2024 · 서울월드컵경기장 2026 · 경기도 2026)으로 **다회용기 전환이 확산** 중이다. 그러나 전국 야구장 매장의 99.7%가 아직 일회용품을 쓴다(2026.6). 병목은 **회수 후 세척**이다.
- 공공·민간 세척센터(청주·양평, 일 2만 개)는 본세척은 자동화됐지만 **분류·애벌세척·랙 적재는 사람의 손**이다. 경기 직후 수천 개가 몰리는 젖은 반복 노동이라 인력 확보가 어렵다.
- 환경부·식약처 「다회용기 세척 위생기준 가이드라인」(2023.7)은 세척 공정과 **반납 수량의 전산 관리**를 요구한다. (근거: [ref/법규_산업조사.md](ref/법규_산업조사.md))

### 1.2 목표
두산 M0609 1대 + OnRobot RG2로 **반납된 그릇·컵의 예비세척 전처리**를 자동화한다. 반납 구역에 놓인(겹쳐 있어도 되는) 용기를 찾아 집어 **잔반을 무게로 판정·제거**하고, **스펀지 고정틀에서 안쪽을 닦고**, **헹굼 모션 후 식기세척기용 팔레트의 정해진 칸·각도로 적재**한다. 본세척은 식기세척기가 한다.

| ID | 비즈니스 요구사항 |
|---|---|
| **BR-01** | 사람이 하던 전처리(잔반 제거 → 닦기 → 헹굼 → 팔레트 적재)를 협동로봇 1대로 자동화한다. |
| **BR-02** | 잔반이 남은 용기를 무게로 걸러 세척기 오염과 재작업을 줄인다. |
| **BR-03** | 처리 수량·판정·소모품 사용을 전산으로 기록해 위생 지침의 기록 요구를 충족한다. |
| **BR-04** | 카메라·전용 설비 없이 협동로봇 + 스펀지 고정틀 + 표준 팔레트만으로 구성해 매장·게이트 단위 소형 셀로 설치할 수 있게 한다. |
| **BR-05** | 시작 버튼 1회로 반납 구역의 용기를 사람 개입 없이 연속 처리하고, 오류가 나도 격리·재개로 운영을 이어간다. |

### 1.3 핵심 기능 (역할 = 기능)
| # | 기능 | 담당 | 설명 |
|---|---|---|---|
| F1 | 파지·이송·적재 | 한석형 | 반납 구역 안을 **탐색하며** 그릇·컵을 집고(파지 폭으로 확인), 스테이션 간 이송하고, **스펀지 홈에 안착 놓기(어긋나면 탐색 보정)**, 툴을 픽업·반납하고, 팔레트의 정해진 칸·각도로 적재한다. |
| F2 | 무게·털기·헹굼 + 흐름 | 민범진 | 무게로 잔반 판정 → 잔반통 위 털기 → 재측정 폐루프, 헹굼 담금·물 털기, 그리고 전체 공정 순서·실패 복구를 맡는 **메인 프로그램 `flow_node`**(f1·f2·f3의 함수를 차례로 부른다). |
| F3 | 접촉 닦기 + 공용 로봇 함수(`cobot_common`)의 힘 함수·패키지 정리 | 박진용 | 수세미 툴(그릇)·수세미 솔(컵)로 일정한 힘으로 **안쪽만** 닦기(동작이 달라 함수 분리), 세제 담금 모션, 스펀지 고정틀 제작. |
| F4 | 시스템 모니터(웹 HMI) + PM | 황인재 | 웹 화면에서 시작·일시 정지·재개, 단계·수량·소모품·연결 상태·오류 로그·이력 표시, SQLite 기록. |

## 2. 범위

| 시나리오 | 내용 | 종료 조건 |
|---|---|---|
| **S1 그릇** | 반납 구역 고정 슬롯 파지(옆면 세로 파지) → 무게·잔반 털기 → 스펀지 홈 안착 → 수세미 툴로 안쪽 닦기 → 헹굼·물 털기 → 팔레트 적재 | 그릇이 팔레트 지정 칸에 적재, 기록 1행 |
| **S2 컵** | 반납 구역 고정 슬롯 파지 → 홈 안착 → 수세미 솔로 안쪽 닦기 → 헹굼·물 털기 → 팔레트 적재 (🔄 9/22 E25 → 🔄 19:0x **E30 되돌림: 컵도 무게 측정·잔반 버리기** · E29: 컵도 테두리 벽을 위에서 집기) | 컵이 팔레트 지정 칸에 적재, 기록 1행 |
| **S3 연속** | 시작 1회로 **그릇 2개 → 컵 2개**를 순서대로 처리, 실패 시 재시도·격리 후 계속 | 전 용기 처리 또는 격리, HMI 완료 표시 |

### 포함
- M0609 + RG2 단일 셀, ROS 2 Jazzy **노드 2개**(`flow_node` 메인 프로그램 · `hmi_bridge`)와 **기능 패키지 3개**(f1·f2·f3 — 노드가 아니라 flow_node가 부르는 파이썬 함수), 공용 메시지·함수 약속·공용 로봇 함수, **PC 2대**(로봇 제어 PC + HMI PC)
- 용기 **그릇 1규격 2개 + 컵 1규격 2개**. 종류는 **반납 구역**으로 결정(그릇 구역 / 컵 구역). 구역마다 **지정된 고정 슬롯 2개**에 겹치지 않게 놓는다 → **고정 슬롯 파지**(9/19 결정 — 이전 안: 구역 안 위치·겹침 자유 + 탐색 파지) ✅ **9/20 변경(결정기록 E9)**: 반납 구역은 **내리막 공급 구조** — 용기를 꺼내면 뒤 용기가 같은 자리로 내려온다 → 구역마다 집는 자리는 **1개**이고 같은 자리에서 차례로 집는다(슬롯 2개 안은 폐기).
- 로봇 하중 측정(`get_workpiece_weight`)으로 잔반 판정, 털기 재측정 폐루프
- 스펀지 고정틀(용기 모양 홈) 안착과 Move Periodic 탐색 보정
- 힘제어 안쪽 닦기(그릇: 수세미 툴, 컵: 수세미 솔), 세제·헹굼 수조 담금 모션(물 없음)
- **식기세척기용 팔레트 모형**(그릇 2칸·컵 2칸)에 칸·각도 지정 적재
- 실패 코드·재시도·격리·정지·재개, 기록(CSV + SQLite), 웹 HMI

### 제외
- 비전·센서, 용기 종류 자동 판별(구역으로 대체), 뒷면·바깥면 닦기, 본세척·살균·건조·위생 판정
- 실제 물·세제(강사 규정: 물·불·기름 사용 불가 → 모션만), 팔레트 교체·세척기 투입, 뚜껑·수저류·여러 규격, 다중 로봇, 안전 인증

## 3. 기능 요구사항 (FR)

### 3.1 시작·고정 슬롯 파지 (F1·F2·F4)
| ID | 요구사항 |
|---|---|
| **FR-01** | 운영자가 HMI에서 시작을 1회 누르면 시스템은 반납 구역을 **계획된 순서**(그릇 구역 → 컵 구역, 구역당 예상 수량)로 전부 처리해야 한다. 용기 종류는 구역으로 결정된다. |
| **FR-02** | 반납 구역의 용기는 **지정된 고정 슬롯**에 하나씩 놓인다. 로봇은 구역의 슬롯을 **설정된 순서**로 이동하며 각 슬롯에서 힘 상한 감시 하강 → 파지 → **파지 폭으로 성공 판정**해야 한다. 그릇은 옆면(벽)을 세로로, 컵은 옆면을 파지한다. ✅ **9/20 변경(결정기록 E9)**: 반납 구역은 **내리막 공급 구조** — 용기를 꺼내면 뒤 용기가 같은 자리로 내려온다 → 구역마다 집는 자리는 **1개**이고 같은 자리에서 차례로 집는다(슬롯 2개 안은 폐기). |
| **FR-03** | 파지 폭이 범위 밖(빈 슬롯·헛잡음)이면 놓고 **다음 슬롯**으로 간다. 슬롯을 다 돌아도 못 잡으면 구역이 비었다고 판단(`EMPTY_ZONE`)하고 다음 구역으로 넘어가며 기록한다. |

### 3.2 잔반 처리 (F2)
| ID | 요구사항 |
|---|---|
| **FR-04** | (🔄 E25 → E30 되돌림 9/22 19:0x: **그릇·컵 모두**) 파지 후 정지 상태에서 용기 무게를 측정하고, 빈 용기 기준값 + 임계(기본 50 g)를 초과하면 **잔반 있음**으로 판정해야 한다. 임계 미만(20 g 미만 포함)은 측정 감도 밖이므로 "잔반 없음"으로 통과시키고 본세척(식기세척기)이 처리한다. |
| **FR-05** | 잔반 있음이면 잔반통 위에서 **잔반 버리기 동작**(🔄 E24: 물 털기와 다른 동작 — 용기 안의 것을 쏟아 낸다)을 3~5회 수행한 뒤 재측정하고, 기준 이하가 될 때까지 최대 N회 반복해야 한다. **털기·헹굼·물 털기처럼 흔드는 동작 동안에는 파지 힘을 올려 더 꽉 잡고(HOLD), 끝나면 보통 파지(NORMAL)로 되돌려야 한다.** |
| **FR-06** | 반복 후에도 기준을 초과하면 격리 구역에 놓고 기록한 뒤 다음 용기를 처리해야 한다. |

### 3.3 닦기 (F3·F1)
| ID | 요구사항 |
|---|---|
| **FR-07** | 용기를 스펀지 고정틀의 용기 모양 홈에 안착시켜야 한다. 홈에 맞지 않으면 Move Periodic 등 탐색 동작으로 보정하고, 한도를 넘으면 실패로 보고한다. |
| **FR-08** | 그릇: 홀더에서 수세미 툴을 집고, 세제(🔄 9/21 E18: 별도 수조 없이 툴 홀더의 비눗물 컵)에 2~3회 담그는 모션 후, 그릇 **안쪽**을 **바닥에 닿은 자리에서**(접촉으로 바닥을 찾는다) 정해진 궤적을 따라 닦은 뒤 툴을 반납해야 한다 — 바닥 구간은 순응만, 벽면 구간은 **일정한 힘(설정값, 상한 10 N)** 을 유지하고 힘을 기록한다. *(9/20 E6 → E13: "일정한 힘 3~5 N" → 수세미가 물러 목표를 낮춤 · "고정 깊이" → 접촉 깊이가 실행마다 12~17 mm 로 달라 바닥은 힘으로 찾는다, V-03 실기)* |
| **FR-09** | 컵: 홀더에서 수세미 솔을 집고, 컵 안쪽에서 회전·상하 동작으로 닦은 뒤 반납해야 한다. |
| **FR-10** | 닦기 중 힘 상한 초과·시간 초과 시 즉시 후퇴하고 실패 코드로 보고해야 한다. 뒷면·바깥면은 닦지 않는다. |

### 3.4 헹굼·적재 (F2·F1)
| ID | 요구사항 |
|---|---|
| **FR-11** | 헹굼 수조 담금 모션과 물 털기 모션을 수행해야 한다(물은 가정, 진폭·속도는 설정값). |
| **FR-12** | 식기세척기용 팔레트의 **정해진 칸(그릇 2칸·컵 2칸)에 정해진 각도**로 적재하고, 겹쳐 쌓지 않고 다음 빈 칸을 순서대로 사용해야 한다. 삽입 중 걸림(힘 초과)이면 후퇴·재시도하고, 실패 시 격리한다. |
| **FR-13** | 팔레트가 가득 차면 HMI에 알리고 운영자 확인 후 계속해야 한다. |

### 3.5 운영·기록 (F4·F2)
| ID | 요구사항 |
|---|---|
| **FR-14** | HMI는 시작·정지·재개 버튼과 **항상 보이는 일시 정지 버튼**(지금 동작을 마친 뒤 멈춤 — 9/20 결정: "E-STOP"이라 부르지 않는다. 비상정지는 로봇 E-Stop), 모드·현재 단계·용기, 처리 수량(종류별 성공·격리)과 진행률, 소모품 카운트, ROS 연결 상태, 오류 코드·로그, 최근 이력을 표시해야 한다. |
| **FR-15** | 오류로 정지한 경우 운영자가 원인을 제거하고 재개 버튼으로 이어서 처리할 수 있어야 한다. |
| **FR-16** | 용기별 시각·종류·구역·탐색 횟수·무게(전/후)·닦기 힘 로그·판정·팔레트 칸·소요 시간을 CSV와 SQLite에 기록해야 한다. |

## 4. 비기능 요구사항 (NFR)
| ID | 구분 | 요구사항 | 정량 |
|---|---|---|---|
| NFR-01 | 안전성 | 모든 접촉 동작(탐색 하강·닦기·안착·적재)에 힘 상한·후퇴·타임아웃. 첫 실기 저속 20~30%. | 닦기 10 N · 안착 15 N · 삽입 15 N · 탐색 하강 10 N (설정) |

- 용기 그릇 2·컵 2, 잔반 대용품(구슬·쌀 등, ≥100 g)

### 7.2 제약
- 비전·외부 센서 없음. 판단 수단은 파지 폭, 하중 측정(감도 ≈ 20 g), 툴 힘·토크, 위치뿐이다.
- 3D 프린터 없음 → 스펀지 커팅·기성품·폼보드·테이프. 물·불·기름 등 액상 사용 불가(강사).
- 로봇 1대를 4명이 공유. 실기 가능일 9/18~9/23(주말 포함) + 9/29. 9/21은 강의·중간점검으로 저녁만. 9/24~28 불가.

### 7.3 위험과 완화
| 위험 | 영향 | 완화 |
|---|---|---|
| 그릇 옆면(벽) 파지는 폭이 **≈ 2 mm**(9/19 확인)라 빈손과의 간격이 좁다 | 파지 성공 오판 | **폭으로 가른다**(9/19 PM 결정, 무게로 가르지 않음): 그릇 전용 허용 오차를 V-01에서 정하고, 닫는 목표 폭을 기대 폭보다 작게 준다. 흔들리면 핑거 패드를 두껍게 |
| 젖은 용기·흔드는 동작에서 미끄러짐 | 낙하 | **파지 힘 2단계(NORMAL/HOLD)**, 실리콘 패드, 동작 전후 폭 비교로 미끄러짐 검출, 저속 |
| 스펀지 홈 안착 실패 | 닦기 불가 | 홈 여유·챔퍼, Move Periodic 탐색, 한도 초과 격리 |
| 힘제어 중 스펀지 눌림·틀 밀림 | 힘 불안정 | 힘 유지형 제어, 틀 고정, 저속 |
| 하중 측정 감도 부족 | 잔반 오판 | 평균·차동 측정, 임계 50 g, 대용품 ≥100 g |
| 털기 시 충돌 감지 정지 | 중단 | 진폭·속도 제한, V-07 검증 |
| 팔레트 삽입 걸림 | 적재 실패 | 순응·삽입력 감시·재시도, 기준점 티칭 |
| PC 2대 통신 불안 | HMI 끊김 | V-09 검증, 실패 시 PC 1대로 통합 |
| 실기 시간 부족 | 미완성 | 기능별 단독 시험 스크립트, mock 선행, 범위 방어표(SDD §9.9) |
| 두산 파이썬 API는 혼자 도는 스크립트 전제 — 콜백·다른 스레드에서 부르면 교착, 명령이 겹치면 조용히 덮어씀 | 통합 실행에서 로봇 정지·오동작 | **스크립트형 실행 구조**: 로봇 명령은 `flow_node` 메인 스레드 하나(SDD §3.2, TS-01). 실행 뼈대를 팀 코드로 Virtual 확인(V-20) |
| 프로세스가 하나라 기능 함수의 예외가 셀 전체를 멈춤 | 운영 중단 | 실패는 `Result.fail(code)`, flow가 모든 호출을 예외 보호로 감싸 `ROBOT_ERROR` → 안전 자세 → PAUSED |

## 10. 용어
| 용어 | 정의 |
|---|---|
| 반납 구역 | 반납된 용기를 놓는 자리. 그릇 구역·컵 구역 2곳. 구역 안 위치·겹침은 자유 (공정의 입구) |
| 팔레트 칸 | 식기세척기용 팔레트 모형의 정해진 적재 자리 (공정의 출구) |
| 고정 슬롯 파지 | 반납 구역의 지정된 슬롯을 순서대로 돌며 힘 감시 하강 → 파지 → 폭 판정으로 용기를 집는 동작(9/19 이전 이름: 탐색 파지) |
| 프리셋 | 종류별 파지 폭·힘·접근 자세 묶음 (`config/cell.yaml`의 `presets`) |
| 탐색 보정 | 안착 실패 시 Move Periodic으로 주변을 조금씩 움직여 홈을 찾는 동작 |
| 격리 | 실패 용기를 격리 구역에 놓고 다음으로 넘어가는 처리 |
| 기능 함수 | f1·f2·f3 패키지가 제공하고 `flow_node`가 차례로 부르는 파이썬 함수. 이름·인자·반환(`Result`)·코드는 `cobot_api`가 정본 (노드·서비스 아님) |
| 메인 스레드 / 통신 노드 | `flow_node` 프로세스의 두 일꾼. 메인 스레드만 로봇을 움직이고, 통신 노드(백그라운드 실행기)는 HMI 요청·상태 발행·그리퍼 폭 수신만 한다 |
| 공정 완료 | 정해진 힘·시간·경로로 동작을 마친 상태 (위생 판정 아님) |
