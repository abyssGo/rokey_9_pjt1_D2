## 2. 값 (펜던트 판독)

| | 무게 | 무게중심 Cx · Cy · Cz (mm) |
|---|---|---|
| 바꾸기 전 (실습 때 잰 값 — 그대로 쓰던 것) | 1.400 kg | 0.170 · 4.850 · 10.910 |
| 재측정 1회 (자동 측정) | 1.450 kg | 4.650 · −4.310 · −0.800 |
| **재측정 2회 (자동 측정) → 직접 입력해 저장** | **1.440 kg** | **3.980 · −3.210 · 2.450** |

| TCP `GripperDA_v1` | X 0.000 · Y 0.000 · Z 208.000 mm · A 0.00 · B 0.00 · C 0.00 | 바꾸기 전·후 같음 |
|---|---|---|

- 1회 ↔ 2회: 무게 10 g · 무게중심 3.5 mm — 자동 측정의 흔들림 정도 → 측정은 믿을 만하다.
- 실습값 ↔ 재측정: 무게 40 g · 무게중심 12.3 mm — 흔들림보다 확실히 크다 → **실습값이 실제와 달랐다**고 보고 바꿨다.
- 크기 감: 1.44 kg 의 무게중심이 12 mm 어긋나면 손목에 약 0.2 N·m — 손가락 끝(208 mm)에서 약 1 N(≈ 100 g) 의 힘 차이로, 손목 자세가 바뀔 때 드러난다.

## 3. 왜 했나

로봇은 저울이 아니라 **관절 토크로 바깥 힘·무게를 추정**한다. 끝에 달린 그리퍼 무게·무게중심이 컨트롤러에 틀리게 들어가 있으면 자세마다 오차가 달라진다.
9/21 민범진 실기에서 같은 그릇이 자세에 따라 60 g 다르게 읽혔다(z 158 에서 9 g · z 235 에서 68 g). 요구사항(BR-SR §5.2 · SR-04)은 "툴 무게 사전 설정"을 전제로 했는데 일정표에 작업이 없었다.

## 4. 이렇게 했다 — 바꾸지 않은 것이 더 중요하다

1. 저장된 값을 먼저 적었다(위 표 "바꾸기 전").
2. 자동 측정 1회 → 저장하지 않고 비교 → 한 번 더 측정 → 두 값이 비슷해서 2회째 값을 쓰기로 함 → 측정 화면에서 바로 저장하지 않아 **값을 직접 입력**해 저장했다(부호 확인: Cy 는 음수).
3. **새 항목을 만들지 않고 기존 `Tool Weight` 에 덮어썼다.** 박진용 `rig_v03`·`rig_v10` 이 툴 이름 `Tool Weight` · TCP 이름 `GripperDA_v1` 이 아니면 실행을 거부한다(`rig_v03` 은 강제로 `Tool Weight` 로 되돌리기까지 한다).
4. **TCP 는 건드리지 않았다.** `cell.yaml` 의 posx 좌표는 전부 이 TCP 기준이라, 바꾸면 9/21 에 맞춘 좌표(V-22 0.24 mm)가 전부 틀어진다. 관절 좌표(posj)만 영향이 없다.
5. 값은 `cell.yaml` 머리의 "로봇 컨트롤러 쪽 툴 설정" 주석에 적었다(R3).
6. 브링업(sodreal) 뒤 ROS 서비스로 컨트롤러가 쓰는 이름을 확인했다 — 펜던트 화면이 아니라 **우리 코드가 받는 값**이다.
   이 PC 에는 환경설정 문서의 `robottool` 별칭이 없어 원래 명령 두 줄로 봤다:
   `ros2 service call /dsr01/dsr_controller2/tool/get_current_tool dsr_msgs2/srv/GetCurrentTool` · `ros2 service call /dsr01/dsr_controller2/tcp/get_current_tcp dsr_msgs2/srv/GetCurrentTcp`
