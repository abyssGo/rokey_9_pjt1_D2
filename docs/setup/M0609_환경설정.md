# M0609 + RG2 개발 환경 설정 (D-2팀 · GPU 유무 공통)

> **대상**: Ubuntu 24.04 LTS + ROS 2 Jazzy. 팀 PC 4대 공통(GPU 있는 PC는 🎮 표시 단계만 추가). 통합 실행은 PC-A(로봇 제어)·PC-B(HMI) 2대
> **로봇**: 두산로보틱스 M0609 + OnRobot RG2 · 컨트롤러 **192.168.1.100:12345** · RG2 설정 웹 192.168.1.1 · **비전 미사용**
> **팀**: D-2 · `ROS_DOMAIN_ID=60` · 기본은 격리(`ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST`) · PC 여러 대 통합 때만 `team60`

## 🚨 먼저 읽어야 할 7가지 함정

### 함정 1. `DR_init` / `DSR_ROBOT2` import 실패 (가장 흔함)

```
ModuleNotFoundError: No module named 'DR_init'
```

두산 패키지의 파이썬 모듈은 일반 site-packages가 아니라 `install/dsr_common2/lib/dsr_common2/imp` 에 있다.
`.bashrc` 에 `PYTHONPATH` 를 추가하지 않으면 **빌드는 되는데 실행만 안 된다.** → 8단계에서 반드시 등록.

### 함정 2. 포트 12345가 이미 점유됨

에뮬레이터(DRCF)를 껐다고 생각했는데 프로세스가 남아 있으면 브링업이 조용히 실패한다.

```bash
# 점유 확인
ss -tlnp | grep 12345
# 남아 있으면 종료
pkill -f DRCF ; pkill -f drcf
```

### 함정 3. Dart-Platform(티치펜던트)과 ROS 동시 제어 연결

M0609 컨트롤러는 **제어 클라이언트 1개만** 받는다. 티치펜던트에서 제어권을 쥔 상태로 `mode:=real` 브링업을 하면 실패하거나 이상 동작한다. **한쪽을 반드시 끊고** 시작.

### 함정 4. colcon이 venv 안에 설치됨

지난 프로젝트에서 `~/venvs/rokey_venv` 를 만들었다면 그 안에 colcon이 들어갔을 수 있다. 터미널마다 이런 오류가 난다.

```
bash: .../colcon_argcomplete/hook/colcon-argcomplete.bash: No such file or directory
```

```bash
which colcon    # /usr/bin/colcon 이어야 정상
```

**이번 프로젝트 방침**: 비전을 안 쓰므로 ROS 작업에 venv가 필요 없다.
**colcon과 ROS는 시스템에서, venv는 backend(FastAPI) 전용으로만** 쓴다. (13단계)

### 함정 5. 지난 프로젝트의 Fast DDS 화이트리스트 XML

`ros2 topic list` 에 `/rosout`, `/parameter_events` 만 나오면 이게 원인이다.

```bash
grep -n "FASTRTPS_DEFAULT_PROFILES_FILE" ~/.bashrc
```

나오면 **9단계에서 주석 처리**한다 (파일은 지우지 말 것).

### 함정 6. `ROS_DOMAIN_ID` 중복 정의

지난 프로젝트 값(2 등)이 남아 있으면 실행 순서에 따라 값이 섞인다.

```bash
grep -n "^export ROS_DOMAIN_ID" ~/.bashrc     # 활성 줄은 딱 하나(=60)
```

### 함정 7. 🎮 Secure Boot / MOK 등록 (GPU PC 전용 — 없는 PC는 해당 없음)

NVIDIA 드라이버 설치 중 MOK 비밀번호를 설정하면, **재부팅 직후 파란 화면에서 반드시 MOK 등록을 완료**해야 한다.
놓치면 드라이버가 로드되지 않아 `nvidia-smi` 가 실패한다. → 3단계 참조.

#### 🚨 재부팅 시 MOK 등록 (함정 7)

설치 중 **MOK setup** 프롬프트가 나오면 `OK` → 비밀번호 설정 → `OK`.


1. `Enroll MOK` 선택
2. `Continue` → `Yes`
3. 설치 때 정한 비밀번호 입력 → 재부팅 완료

#### 설치 확인


### 8-8. 워크스페이스 겹치기(overlay) — 두산 파일을 두 번 받지 않는 이유

ROS 2는 워크스페이스를 겹쳐 쓴다. 드라이버 워크스페이스를 먼저 `source`하고 그 위에 우리 워크스페이스를 빌드하면, 우리 패키지가 두산 패키지(`dsr_msgs2` 등)를 그대로 찾는다.

```
~/ws_cobot_pjt/ws_dsr/     ← 두산 드라이버. 한 번 빌드, 수정 안 함
$PREWASH_WS/          ← 우리 저장소. src/ 에 우리 패키지 8개만
```

```bash
# 빌드·실행은 항상 이 순서 (별칭 sod → cbc/soc 가 이 순서를 지킨다)
source ~/ws_cobot_pjt/ws_dsr/install/setup.bash
cd $PREWASH_WS && colcon build --symlink-install && source install/setup.bash
```

경로가 꼬이는 경우는 **같은 이름의 패키지가 두 워크스페이스에 모두 있을 때**뿐이다(나중에 source한 쪽이 이긴다). 규칙 세 개:
1. 우리 `src/`에 두산 패키지를 복사하지 않는다.
2. source 순서는 드라이버가 먼저, 우리가 나중이다.
3. `DR_init` 경로(PYTHONPATH)는 드라이버 워크스페이스를 가리킨다(8-7).

우리 워크스페이스에서 `colcon build`를 해도 두산 패키지는 다시 빌드되지 않는다. `package.xml`에 `dsr_msgs2`를 의존성으로 적으면 설치된 것을 찾아 쓴다.

```bash
# --- 실기 점검 (강의 6-1): 로봇 모드 · 툴 · TCP 확인 ---
alias robotmode='ros2 service call /dsr01/dsr_controller2/system/get_robot_mode dsr_msgs2/srv/GetRobotMode'
```

## 12. 좌표 티칭 준비

비전을 안 쓰므로 **좌표가 곧 프로그램**이다. 좌표·힘·횟수·탐색점은 전부 `src/cobot_common/config/`의 `cell.yaml`(공용)·`params.yaml`(기능별 절)에 두고, 코드에서는 키 이름(변수)으로 부른다. **ROS 파라미터 형식(`ros__parameters`)이 아니라 평문 YAML**이며 `cobot_common.config.load()`가 읽는다. 스키마는 `docs/03_설계_SDD.md` §4.3.

```yaml
# src/cobot_common/config/cell.yaml (발췌) — 팀 공용 좌표·속도·프리셋. 단위는 키 이름 접미사로
cell:
  limits: {vel_free_pct: 60, vel_carry_pct: 30, safe_z_mm: 150, contact_limit_n: 10, insert_limit_n: 15, timeout_s: 10}
  stations:
    HOME:  {posj: [0.0, 0.0, 90.0, 0.0, 90.0, 0.0]}
    WEIGH: {posx: [______, ______, ______, ______, ______, ______]}
  zones:
    RET_B: {frame: RETURN, origin_posx: [______, ______, ______, ______, ______, ______],
            search: {offsets_mm: [[0,0],[40,0],[-40,0],[0,40],[0,-40]], max_attempts: 5, descend_max_mm: 80}}
```

**티칭 절차(9/19 오전 공통 세션)**: Dart Platform으로 자세를 잡고 현재 좌표(`get_current_posx`)를 읽어 YAML에 적는다 → ROS에서 저속으로 재현 → 🚨 티치펜던트 **제어권 해제** 후 브링업(함정 3). 팔레트·반납 구역은 기준점 1개만 티칭하고 나머지는 오프셋으로 만든다.

## 13. (선택) HMI용 venv — ROS와 분리해서 쓰기 (PC-B, F4만)

HMI(F4) 담당자만, PC-B에서 한다. **ROS 빌드에는 venv를 쓰지 않는다.** (함정 4)

```bash
mkdir -p ~/venvs && cd ~/venvs
python3 -m venv hmi            # --system-site-packages 쓰지 않음
source ~/venvs/hmi/bin/activate
pip install fastapi "uvicorn[standard]" websockets     # SQLite는 파이썬 내장(sqlite3)
which colcon                     # 🚨 /usr/bin/colcon 이어야 함. venv 경로면 잘못된 것
deactivate
```

> venv 안에 `colcon` 이나 `rclpy` 를 pip로 깔지 않는다. ROS는 시스템 것을 쓴다.

## 🔧 자주 겪는 문제 빠른 참조

| 증상 | 확인 | 해결 |
|---|---|---|
| `No module named 'DR_init'` | `echo $PYTHONPATH \| grep dsr` | `.bashrc` PYTHONPATH 추가 → `source ~/.bashrc` |
| 브링업이 조용히 실패 | `port12345` | `killdrcf` 후 재실행 |
| 실기 브링업 거부 | 티치펜던트 제어권, `robotmode` | Dart Platform 연결 해제 후 재시도 |
| `colcon-argcomplete.bash: No such file` | `which colcon` | venv 비활성화, 시스템 colcon 사용 |
| 토픽이 2개만 보임 | `grep FASTRTPS ~/.bashrc` | 화이트리스트 XML 주석 처리 |
| 팀원 노드가 안 보임(통합 때) | `rosinfo` | 기본이 격리라 정상 → 두 PC 모두 `team60`, 같은 스위치. 안 되면 Discovery Server |
| 두산 패키지가 두 곳에 있음 | `ros2 pkg prefix dsr_msgs2` | 우리 `src/`에서 두산 패키지 삭제, source 순서 ws_dsr → rokey_pjt01_ws |
| `bash: n: No such file or directory` | 명령어에 `______`/`<n>` | 실제 값으로 교체 |
| `nvidia-smi` 실패 | `lsmod \| grep nvidia` | MOK 등록 재시도 또는 Secure Boot 비활성화 |
| 빌드 중 PC 멈춤 | 메모리 | `colcon build --parallel-workers 2` |
| `rosdep` 실패 | `$ROS_DISTRO` | `source /opt/ros/jazzy/setup.bash` 먼저 |
