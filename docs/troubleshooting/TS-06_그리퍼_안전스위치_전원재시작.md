# TS-06 그리퍼 안전 스위치(S1·S2)가 걸리면 전원을 다시 넣어야만 풀린다 — `/onrobot/restartPower` 는 부르면 안 된다

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-09-21 |
| 발견 | 민범진 (V-01·V-05·V-23 실기 중 반복해서 걸림) |
| 영향 | **그리퍼를 쓰는 모든 기능** — F1 파지·이송·적재, F2 털기·담금, F3 툴 픽업·반납 |
| 관련 | [TS-05](TS-05_DR_Error_rclpy_shutdown_복구.md) 와 비슷한 모양(복구 도구가 필요한 상태)이지만 **다른 건** — 그건 두산 팔, 이건 OnRobot 그리퍼 |
| 상태 | **코드 적용 완료 · 🟡 실기 확인 전**(§7 남은 확인). 확인 전까지는 사람이 전원을 다시 넣는 길도 열어 둔다 |

## 1. 증상

그리퍼에 명령을 보냈는데 **폭이 하나도 안 변한다.** 오류도 안 난다 —
드라이버는 `success = True` 를 돌려주고(§TS 없음: 원래 무조건 True 다), 로그도 조용하다.

```
[WARN] 그리퍼가 "폭 2.0 mm 로 잡기" 에 **전혀 움직이지 않았다** (폭 10.72 mm 그대로).
```

다시 실행해도, 브링업을 다시 띄워도 그대로다. **컴퓨트박스 전원을 뽑았다 꽂아야** 살아난다.

## 2. 무슨 일인가 — 안전 스위치

RG2 손가락에 옆으로 큰 힘이 걸리면 그리퍼 안의 **안전 스위치(S1·S2)** 가 걸린다(RG2 매뉴얼 §6.2.3).

> **멀티탭의 과부하 차단 버튼**과 같다. 한 번 튀면 플러그를 뺐다 꽂아도 소용없고,
> 차단 버튼을 눌러 줘야 — 여기서는 **툴 전원을 껐다 켜야** — 살아난다.

상태는 컴퓨트박스의 레지스터에 남아 있다. 드라이버(`comModbusTcp.getStatus`)는 이것을 **읽으면서도
밖으로 내보내지 않는다** — `/onrobot_joint_states` 에는 위치와 힘만 싣는다. 그래서 지금까지
우리 코드는 "폭이 안 변하네?" 하고 **짐작만** 했다.

| 상태 레지스터 (258번 칸부터, 툴 번호 65) | 뜻 |
|---|---|
| 270 · 271 | S1 **눌림** · S1 **걸림** ← 걸림이 0 이 아니면 전원을 다시 넣어야 한다 |
| 272 · 273 | S2 눌림 · S2 걸림 |
| 274 | `safety` — 🟡 의미를 매뉴얼로 확인하지 못했다. 보여만 주고 판정에는 쓰지 않는다 |

## 3. 🚨 드라이버의 `/onrobot/restartPower` 를 부르면 드라이버가 죽는다

배포본에 전원 재시작 서비스가 **있긴 하다.** 그런데 호출부의 인자 이름이 틀렸다.

```python
# ws_dsr/src/onrobot-ros2/onrobot_rg_control/.../comModbusTcp.py  restartPowerCycle()
message = [2]
self.client.write_register(address=0, values=message, slave=restart_address)
#                                     ^^^^^^ pymodbus 는 write_register(address, value, slave) 다
```

`values=` 는 `write_registers`(복수)의 인자다. 그래서 `value` 가 빠진 채 호출되어 **TypeError** 가 나는데,
이 자리가 **서비스 콜백 안**이라 예외가 실행기 밖으로 튄다 → 그리퍼 드라이버 노드가 통째로 내려간다.

> 원본 OnRobot 코드는 `value=2` 로 맞게 돼 있다. 배포본이 고치다 깨진 것으로 보인다.
> 🚨 `ws_dsr` 은 **수정 금지**(강사 배포)라 우리가 고치지 않는다.

## 4. 해결 — 같은 Modbus 쓰기를 우리가 올바른 인자로 보낸다

`cobot_common/gripper.py` 에 두 함수를 넣었다. 강사 배포본은 건드리지 않는다.

```python
cc.grip_safety()                  # 🟢 읽기만 — 걸렸나? {'tripped': True/False, 's1_triggered': 1, …}
cc.grip_reset(empty_hand=True)    # 🚨 툴 전원을 껐다 켠다 (쥔 것은 떨어진다)
```

`grip_reset` 이 실제로 하는 일은 한 줄이다 — **상자 번호 63 의 0번 칸에 2 를 쓴다**(툴 번호 65 가 아니다).
그 뒤 ① 풀렸는지 다시 읽어 확인하고 ② 드라이버가 살아남았는지(`/onrobot_joint_states` 가 다시 오는지) 본다.

설정은 `src/cobot_common/config/params.yaml` 의 `f2.gripper_box`(주소·번호·기다리는 시간).

그리고 "명령했는데 폭이 안 변한다" 를 만나면 `gripper.py` 가 이제 **짐작하지 않고 읽어서** 말한다.

```
[ERROR] 🚨 그리퍼 **안전 스위치가 걸렸다** — "폭 2.0 mm 로 잡기" 명령이 무시됐다 (폭 10.72 mm 그대로).
        S1 눌림 0/걸림 1 · S2 눌림 0/걸림 0 · safety 0. 손가락에 걸린 것을 치운 뒤
        cc.grip_reset(empty_hand=True) 로 툴 전원을 껐다 켠다 (쥔 것은 떨어진다)
```

## 5. 쓰는 법

```bash
soc && python3 src/cobot_common/test/rig_grip_reset.py check    # 🟢 읽기만 — 아무것도 안 움직인다
soc && python3 src/cobot_common/test/rig_grip_reset.py watch    # 계속 지켜본다 (Ctrl+C 로 끝)
soc && python3 src/cobot_common/test/rig_grip_reset.py reset    # 🚨 전원 재시작 — yes 를 쳐야 실행
```

🟢 `check`·`watch` 는 **브링업이 없어도 된다.** 상자와 직접 말하기 때문이다.
종료 코드 0(정상) / 1(걸려 있음·못 풀었음) / 2(상자와 말이 안 통함·취소) / 130(Ctrl+C).

## 6. 🚨 주의 3가지

1. **전원을 다시 넣으면 쥐고 있던 용기를 떨어뜨린다.** 그래서 `grip_reset()` 은 `empty_hand=True`
   로 손이 빈 것을 밝히지 않으면 **거부한다**(쥔 것을 떨어뜨리지 않는다). 자동으로 부르는 자리는 아직 없다 —
   `gripper.py` 는 걸린 것을 **알려만 주고 스스로 풀지 않는다**.
2. **그리퍼 드라이버가 같이 죽을 수 있다.** 툴 전원이 끊긴 순간 드라이버가 상태를 못 읽으면
   타이머 콜백에서 터진다. `grip_reset()` 이 `driver_alive=False` 로 알려 주며, 그때는 브링업을 다시 띄운다.
3. **연결이 하나 더 붙는다.** 드라이버가 이미 50 Hz 로 상자를 물고 있다. 그래서 우리 연결은
   **부를 때마다 붙었다 뗀다**(오래 들고 있지 않는다).
