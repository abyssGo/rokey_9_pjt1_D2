## 1. 증상
| # | 상황 | 증상 |
|---|---|---|
| A | 프로그램 기동 | `AttributeError: 'NoneType' object has no attribute 'create_client'` — 뜨자마자 죽는다 |
| B | 서비스 콜백 안에서 첫 로봇 명령 | `RuntimeError: Executor is already spinning` 또는 **무한 대기**(타임아웃 없음) |

## 2. 원인 — 두산 API는 "혼자 도는 스크립트"를 전제로 만들어졌다
ROS 노드에는 **실행기**(executor)가 붙어 있다. 실행기는 노드로 들어오는 서비스 요청·응답·타이머를 받아 해당 함수를 실행해 주는 담당자이고, 기본적으로 **한 번에 하나만** 처리한다.

**A.** `DSR_ROBOT2.py`는 **import되는 순간** `g_node = DR_init.__dsr__node`를 읽어 고정하고 곧바로 `g_node.create_client(...)`를 수백 번 부른다. 노드를 넣기 전에 import하면 `None`이라 그 자리에서 죽는다.

**B.** 두산의 모든 로봇 명령은 안에서 이렇게 한다(241곳, 타임아웃 지정은 24곳뿐).
```python
future = _ros2_movej.call_async(req)
rclpy.spin_until_future_complete(g_node, future)   # 응답이 올 때까지 "직접" 실행기를 돌린다
```
스크립트에서는 실행기를 돌리는 사람이 없으니 괜찮다. 서비스 콜백 안에서는 **이미 실행기가 그 콜백을 실행하는 중**이라, 같은 실행기를 또 돌리려다 오류가 나거나 응답을 열어 줄 사람이 없어 무한 대기한다.
> 창구 직원이 한 명인 은행에서, 직원이 손님 일을 처리하다 본점 회신을 기다리는데 그 회신도 같은 창구로 온다.

**B′.** `rclpy.spin_until_future_complete(node, …)`는 노드를 전역 실행기에 넣었다가 끝나면 뺀다. rclpy는 노드를 새 실행기에 넣을 때 **원래 실행기에서 빼 버린다**(`rclpy/node.py`의 `executor` setter). 그래서 첫 명령이 끝나면 그 노드는 어느 실행기에도 속하지 않게 되고, 다음 서비스 요청은 도착해도 꺼내 줄 실행기가 없다.

**C.** `dsr_controller2`의 이동 서비스는 동기 서비스다(끝날 때까지 응답 없음, 취소·피드백 없음). 명령 중재가 없어 나중 명령이 앞 명령을 덮어쓴다.

**D.** DRL 매뉴얼은 `check_force_condition`이 `True/False`를 돌려준다고 하지만 실제 `DSR_ROBOT2.py:5478`은 **만족 `0` / 아니면 `-1`**이다(`check_position_condition`도 같다). 파이썬에서 `0`은 거짓이다.

참고: 두산의 클래스 API `CDsrRobot`도 대기 방식이 같고(112곳), 우리 설치본은 서비스 이름을 `/motion/move_joint`로 찾아(실제는 `/dsr01/dsr_controller2/motion/move_joint`) **스크립트에서도 무한 대기**한다 → 쓰지 않는다([cls.py](ts01_repro/cls.py)).

## 4. 해결 = 실행 구조 변경 (SDD §3.2)
- 로봇을 움직이는 코드는 **전부 `flow_node`의 메인 스레드에서 차례로** 실행한다. f1·f2·f3는 노드가 아니라 **함수 모듈**이다 → B·B′·C가 생길 자리가 없다.
- `cobot_common.init(name)`이 DSR 전용 노드를 만들어 넣은 **뒤에** 두산 API를 import한다 → A.
- `cobot_common.force_reached()`가 `== 0` 비교를 감싼다 → D. 기능 패키지는 `DSR_ROBOT2`를 직접 import하지 않는다.
- `/flow/*` 서비스·상태 타이머·그리퍼 폭 구독은 **통신 노드**(백그라운드 실행기)가 맡고, 콜백은 값 저장·깃발 세우기만 한다.
- flow는 모든 기능 함수 호출을 예외 보호로 감싸고, 끝낼 때 `cobot_common.shutdown()`으로 정지 명령을 먼저 보낸다.

## 5. 재발 방지
- 같은 함수를 **연속 3회 이상** 불러서 시험한다. 증상 B′처럼 "첫 번째만 되는" 결함은 한 번 호출로는 보이지 않는다(SDD §9.3).
- 로봇 함수를 콜백·타이머·다른 스레드에서 부르지 않는다. 통합 중 터미널에서 드라이버 서비스를 손으로 부르지 않는다(증상 C).
- 움직이는 중에 프로그램을 강제로 죽였으면 브링업부터 다시 띄운다.
- 두산 함수의 반환값은 DRL 매뉴얼이 아니라 **설치된 `DSR_ROBOT2.py`**에서 확인한다.
