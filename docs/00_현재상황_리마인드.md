### 정지 · 재개 · 중단 (IRD §6)

- **정지(`/flow/stop`)** = 즉시 일시 정지(이동 도중에도). **재개** = 하던 동작을 이어서. 실패로 멈춘 PAUSE 에서 재개하면 **실패한 그 단계부터 다시**(`ROBOT_ERROR` 만 다음 용기)
- **중단(`/flow/abort`)** = PAUSED 에서만 · `ROBOT_ERROR` 면 거부 · 정리 순서 **HOME → 툴 반납 → 격리 → HOME**(E11) → `ISOLATED`
- **Ctrl+C** = 개발자용 정지(`cc.init` 이 가로채 → `shutdown` 이 move_stop DR_QSTOP). **E-Stop 은 언제나 최우선**

## 3. 구조 — 코드가 어떻게 생겼나

- **노드는 2개뿐**: `flow_node`(PC-A · 로봇 PC — **메인 스레드가 기능 함수를 순서대로 부른다**) · `hmi_bridge`(PC-B — FastAPI + rclpy · 웹 화면은 **그 PC 브라우저에서만** 접속, E10)
- **f1·f2·f3 은 노드가 아니라 함수 모듈**이다. 반환은 `cobot_api.*Result`. 공정상 있을 수 있는 실패는 **예외가 아니라 `Result.fail(code)`** (예외는 로봇 이상일 때만)
- **`cobot_common`** = 공용 로봇 함수(`import cobot_common as cc`) — 이동 `move_to`·`move_rel`·`move_joint_rel`·`move_joints_via`(스플라인)·`safe_retreat` · 그리퍼 `set_grip_preset`(옆면 재파지 힘 기억) · 시간 상한은 배속·거리에 맞춰 늘고 최소 30 s · 멈춤 `pause`·`resume`·`halt`·`clear_halt`·`stop` · 그리퍼 `grip`·`grip_level`·`release`·`grip_width` · 힘 `force_on/off`·`contact_down`·`periodic_search`·`safe_retreat`·`move_periodic`·`joints`·`stop_now` · 무게 `weigh`. **파일마다 주인이 있다**(§4)
- 🚨 **실행 뼈대 규칙(SDD §3.2)**: 로봇 함수는 **메인 스레드에서만** · 콜백은 **깃발 세우기·값 읽기만** · 기능 함수 안에서 `rclpy.init`/`spin`/노드 생성 금지 · `DSR_ROBOT2` 직접 import 금지
- **설정**: `src/cobot_common/config/cell.yaml`(좌표 · 속도 · 힘 상한 · 그리퍼 프리셋) + `params.yaml`(`f1`·`f2`·`f3`·`flow`·`hmi` 절 — **자기 절만** 고친다). 숫자를 코드에 적지 않는다(AGENTS 규칙 6)
- **인터페이스**: `/flow/start`·`stop`·`resume`·`abort`(Trigger) · `/flow/state`(FlowState 2 Hz) · `/flow/event`(FlowEvent 용기마다). ❌ **`/cell/force` · `/cell/gripping` 은 없다**(E21 — 만들지 않는다)
- 실행: `ros2 launch prewash_bringup prewash.launch.py vel_scale:=0.5`(시연 · E40) → `/flow/start` · 한 바퀴만: `PREWASH_VEL_SCALE=0.3 python3 src/f2_sense_flow/test/rig_flow_once.py --kind CUP --mock ""` · 가짜로 돌릴 때 `use_mock:="f1,f3"` · 🚨 로봇 프로그램은 **한 번에 하나** · 단계별 rig 는 프로그램마다 그리퍼 힘·프리셋 기억이 안 이어진다(담금·털기는 흐름 안에서)

## 6. 🚨 안전 — 매번

- 🚨 **로봇을 움직이기 전에 툴·TCP 이름을 확인한다**(9/22 사고 · 황인재 승인) — `ros2 service call /dsr01/dsr_controller2/tcp/get_current_tcp dsr_msgs2/srv/GetCurrentTcp` → `GripperDA_v1` · `ros2 service call /dsr01/dsr_controller2/tool/get_current_tool dsr_msgs2/srv/GetCurrentTool` → `Tool Weight`. 비어 있거나 다르면 **움직이지 말고** 브링업을 끈 뒤 펜던트에서 다시 고른다(ROS 명령으로는 안 된다). 🚨 E26: **프로그램·시험 도구도 확인만** — ROS 로 set_tool/set_tcp 하거나 MANUAL↔AUTONOMOUS 모드를 오가지 않는다. 9/22 오전 선택이 풀려(10:54~11:17 사이 · 원인 미확인) **posx 이동이 손끝 208 mm 아래로** 갔고(그릇이 바닥에 닿음) 무게가 1.3 kg 로 고정됐다. 그 시간에 찍은 좌표는 플랜지 값이라 쓰면 안 된다
- 🔗 **그리퍼 케이블(전선)을 느슨하게 둔다**(9/22 황인재 관찰) — 케이블이 팽팽하면 힘·무게 값이 ±25 g 이상 흔들린다(늘려 주니 ±10 g 안팎). 자세마다(특히 잔반통 J6 180° 회전 · HOME) 당기지 않는지 본다. 무게·힘 실기(V-02 · V-07 · INT-12a · 닦기)는 케이블 상태를 먼저 맞춘다 · ✅ PR #75: 무게 잴 때 표본 퍼짐 > 50 g · 시작 전 HOME 정지 흔들림 > 60 g 이면 **로그에 🔗 경고**(멈추지 않음 · 기준값은 임시) — 경고가 보이면 케이블부터
- 🔌 **실기를 끝낼 때는 연결부터 끊고 랜선을 뽑는다**(9/22 황인재) — ① 돌리던 프로그램 터미널 Ctrl+C → 브링업 터미널 Ctrl+C ② 다 꺼진 것을 확인한 뒤 랜선을 뽑는다(다음 사람에게 넘길 때도). 연결된 채로 랜선부터 뽑지 않는다 — 9/22 툴·TCP 선택 풀림의 원인은 못 찾았지만 연결 도중 끊김을 없애 막는다. 넘겨받은 사람은 꽂고 브링업한 뒤 두 이름부터 확인
- 🚨 **TS-08 (9/22 17:27 실기 충돌 · 🔴 17:07 은 착오)** — `f2.dip`·`f2.shake(RINSE)` 는 **수조 안(z −13.6)** 에서 끝난다. 거기서 `cc.move_to('HOME')` 관절 이동 → 그리퍼가 테이블을 쓸고 비상정지(툴 전원 끊겨 그리퍼 드라이버까지 죽음). PR #77 로 f2 시험대·`abort_container` 는 **먼저 곧게 위로(`safe_retreat` 235 mm)** 간다. 원인은 민범진 로그로 확정(황인재 세션이 쉬던 17:12~17:31 틈 · TCP 풀림 17:38 은 10분 뒤). 🚨 18:11 빈 그릇 자리 −117.5 g(기준값 −12 → 105 g 영점 이동) → PR #78: 하한 미달이면 **폭으로 파지 재확인**. 🟡 다른 시험대(rig_f1·rig_f3·rig_weigh_*)는 아직 — 시작 전 로봇이 낮으면 손으로 먼저 올린다. `docs/troubleshooting/TS-08_*.md`
- **로봇 위치를 모르면 자동으로 움직이지 않는다** — `MoveIncomplete` · `MotionHalted` · 관절 감시 정지. 힘·순응만 끄고 **사람이 복구**. (힘 상한은 위치를 아니까 설계대로 후퇴)
- 첫 실기는 **vel_scale 0.3** · 손은 **E-Stop** · 로봇 주변을 비운다
- 로봇 **툴 회전 속도 한계 225 °/s** — 넘으면 컨트롤러가 거절(알람 1212)
- 6번 관절 큰 회전·특이점 주의 — 9/21 08:40 케이블 꼬임(원인은 팔꿈치 특이점 J3 = 1.7°)
- **Virtual 결과를 믿지 않는 것**: Move Periodic 회전은 Virtual 에서 rx↔rz 가 뒤바뀐다. 실기에서 TOOL rz = 6번 관절, TOOL rx = 4번 관절
- **그리퍼는 시뮬레이션(가상 로봇)에서 검증되지 않는다**(9/21 팀 보고) — 가상 로봇에는 OnRobot 그리퍼가 없다. 그리퍼가 얽힌 확인(폭 · 힘 전환 · 놓기 · 파지 실패)은 **실기로만** 한다. 가상 로봇으로는 팔 동작·흐름만 본다
- 브링업이 이미 떠 있으면 새로 띄우지 않는다(겹치면 에뮬레이터가 바뀐다) · 끌 때는 내가 띄운 것만
- 그리퍼 안전 스위치가 걸리면 컴퓨트박스 전원을 다시 넣어야 풀린다(RG2 매뉴얼 §6.2.3)
